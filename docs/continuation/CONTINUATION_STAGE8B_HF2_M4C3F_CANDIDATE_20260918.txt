Candidate solution:
1. Add NonContentResolutionExecutionReceipt as a receipt type distinct from ResolutionExecutionReceipt.
2. It is valid only for defer/remain-silent.
3. Its channel is local-runtime-noncontent.
4. Its status is local-noncontent-action-committed.
5. It records the selected action, local effect, current event/turn, pre-knot digest, and pre-residual.
6. It carries hard false fields for content_emitted, outward_transport_performed, peer_delivery_confirmed, peer_read_confirmed, peer_understanding_confirmed, and peer_reply_causation_confirmed.

8. It does not run the independent expression selector and does not mark expression pending because no content is expressed.
9. Client/serialized receipt objects cannot mark execution; only the identical in-process receipt capability inside the trusted transaction can do so.
10. owner_command, operator realization override, endogenous and nonconversational events cannot be converted into local non-content execution by this path.
11. The receipt itself never trains consequence geometry.
12. Later learning still requires a distinct later nonempty USER_MESSAGE, time ordering after receipt completion, unchanged pre-knot/pre-residual binding, security_admissible native post-state, and the existing nonworsening gate.
13. A malformed/tampered non-content effect cannot authorize outcome learning.
14. Persistence failure rolls back speech-act state and security checkpoint.
15. Existing clarify/ask ASGI content-send receipt remains unchanged.

NON-CONTENT EFFECTS
defer:
defer-current-turn-resolution
Meaning: the local runtime commits the selected decision not to outwardly resolve this current turn now. It does not promise a future message or schedule work.

remain-silent:
close-current-turn-without-outward-realization
Meaning: the local runtime commits the selected no-outward-realization action for this turn.

These effects distinguish the local control actions without inventing semantic text. Neither effect asserts peer observation.
