M4C3M PURPOSE
Verification-first inspection of authenticated private-Room client playback telemetry under network uncertainty, duplicate submission, server restart and Room-session rotation.

A concrete defect was found in exact post0017:
postClientMediaEvent() retried the HTTP 409 provenance race but a thrown fetch/network error exited immediately.
If the server had already durably persisted playing but the HTTP response was lost, the browser could clear its playback_session_id and lose continuity to the matching ended event.

The server-side telemetry substrate was already persistently idempotent, so the bounded repair is to retry the exact same payload and playback_session_id when response outcome is ambiguous.
