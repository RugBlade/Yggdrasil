WHAT M4C3G IMPLEMENTS
1. LocalEventStore.latest_state now fails closed with PersistedStateValidationError when the newest persisted NoeronState is unparseable, instead of silently treating corruption as no saved state and booting a fresh identity.
2. Startup checks pending resolution execution provenance before normal runtime migration/work begins.
3. A valid persisted pending content receipt must match action, event, turn, pre-knot digest, pre-residual, origin, last execution receipt and the independent expression pending linkage.
4. A valid persisted non-content receipt must match the same speech-act provenance while preserving content_emitted=false, outward_transport_performed=false, all peer-uptake flags=false and no expression pending state.
5. If the newest state replays a receipt already durably recorded as consumed in earlier SQLite state history, startup recovers to the newest prior valid post-consumption state and persists that recovery. It does not learn again.
6. Parseable but mismatched pending state is cleared as non-learnable and written to provenance/audit with all authority flags false.
7. An unparseable newest state fails closed rather than fabricating a fresh runtime state.
8. Recovery logic does not select a speech act, author content, create an observation, change consequence weights, or claim peer delivery/read/understanding/reply causation.
9. SQLite history inspection is restart-integrity provenance only and is not cognitive retrieval or semantic memory.

TRUE PROCESS-RESTART EVIDENCE
The focused tests construct real post-0013 execution receipts through the trusted execution paths, then launch brand-new Python subprocesses and brand-new Noeron instances pointed at the same isolated SQLite database.
They prove:
- content and non-content pending receipts reconstruct with linked pre-state;
- defer/remain-silent cannot be executed a second time merely because a process restarted;
- one later admissible conversational USER_MESSAGE consumes a persisted pending outcome at most once;
- a replayed already-consumed receipt does not add a second consequence observation;
- action, pre-knot and content-expression linkage mismatches are non-learnable;
- malformed/unparseable latest persisted receipt state fails closed;
- restart recovery does not create cognitive-memory or relationship authority.
