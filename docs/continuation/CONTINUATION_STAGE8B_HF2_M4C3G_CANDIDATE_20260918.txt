WHY M4C3G NEEDS A PATCH
A true new-process/same-SQLite probe showed that valid pending ResolutionExecutionReceipt and
NonContentResolutionExecutionReceipt state already reconstructs correctly after restart.
However, a replayed older state row containing an already-consumed pending receipt could be
made the newest SQLite state. A brand-new Noeron instance then loaded that stale pending state
and a later admissible conversational USER_MESSAGE could train the same receipt a second time.
This is a restart-integrity/double-learning defect. It does not concern native act choice.

CANDIDATE CHANGE — TWO RUNTIME FILES ONLY
1. src/noeron/memory.py
- Adds PersistedStateValidationError.
- latest_state() now fails closed if the newest persisted NoeronState cannot be validated,
  rather than silently returning None and allowing a fresh-state fallback.
- Adds a bounded state-history integrity lookup for a receipt ID. It searches only for
  durable evidence that the same execution receipt was already consumed and returns the
  newest prior valid state after consumption.
- This state-history inspection is explicitly restart-integrity provenance only. It is not
  cognitive retrieval and has zero semantic/preference/relationship/source/deploy authority.

2. src/noeron/orchestrator.py
- Runs persisted resolution execution integrity recovery during process initialization.
- A valid pending content/noncontent receipt is restored without execution or learning.
- Receipt/pre-knot/pre-residual/event/action/origin linkage is checked.
- Content receipts also require the persisted expression receipt/pre-state linkage.
- Noncontent receipts require exact no-content/no-transport/no-peer-evidence invariants and
  no expression pending state.
- If the newest state replays a receipt already durably consumed in prior SQLite history,
  startup recovers to the newest prior valid post-consumption state and persists that recovery.
- A parseable but mismatched pending state is cleared as non-learnable and recorded in
  provenance/audit only.
- An unparseable newest persisted state fails closed; it does not silently boot a fresh identity.
