CANDIDATE MECHANISM
1. Stable keyed presentation/audio DOM reconciliation
- native presentations get a dedicated DOM surface;
- nodes are keyed by NativePresentationRecord.id;
- the existing HTMLAudioElement is reused across unrelated Room snapshot updates;
- same presentation/artifact does not have its src reassigned;
- no autoplay or native-audio programmatic play() is introduced.

2. Narrow browser event vocabulary
- client listens to playing and ended;
- play is not used as the telemetry receipt;
- first playing creates one browser playback_session_id;
- pause/resume in that same browser playback session does not manufacture another first-playing identity;
- ended uses the same playback_session_id and resets client state afterward.

3. Typed telemetry receipt
NativeAudioClientPlaybackTelemetryReceipt is browser media-element telemetry only.
Its audible/hearing/authority fields are Literal[False], so the type cannot be instantiated with a true audible-output/hearing/native-choice/relationship claim.

4. Provenance ordering
playing requires:
- exact NativePresentationRecord;
- exact linked noeron-to-owner audio artifact and hashes;
- genuine native voice presentation provenance;
- an already-durable matching NativeAudioTransportReceipt.

ended additionally requires:
- prior accepted playing;
- same presentation/artifact;
- same owner device;
- exact same Room session-token SHA256;
- same playback_session_id.

ended retains the original playing transport receipt link even if another audio GET occurs later.

5. Persistent anti-replay/idempotency
A dedicated SQLite audit/provenance table uses a persistent unique dedupe identity over:
presentation + artifact + owner device + exact session hash + playback_session_id + event.

Exact logical duplicate playing/ended submissions return the existing receipt and do not append another telemetry journal event.

6. Authentication
The endpoint uses the existing private Room transport guard and current Ed25519 owner-device session.
Legacy bootstrap remains invalid for Room telemetry.
Nonprivate transport remains invalid.
Raw Room session tokens are never stored in telemetry; only the same SHA256 session identity already used by OwnerAuthenticator is stored privately.

7. Zero cognition/learning authority
Client telemetry:
- never marks a resolution speech act executed;
- never trains speech-act consequence geometry;
- never trains expression/private continuation;
- does not consume pending execution state;
- is not cognitive memory;
- creates no preference or relationship meaning.

8. Sanitized outward state
Room snapshot and endpoint response omit owner_session_sha256 and device fingerprint.
They may expose the owner device id and client media event identity for private operator audit.
audible_output_confirmed, peer delivery/hearing/understanding/reply causation and cognitive/native-choice/preference/relationship authority remain false.
